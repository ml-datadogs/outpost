# Запуск пилота Happ

## Заказ одного VPS

1. Войти в существующий аккаунт HOSTKEY. При проверке 20 ноября 2026 года в доступных аккаунту списках серверов было 0 записей. Для старта выбран один узел в Амстердаме. MivoCloud остаётся кандидатом для будущего сравнения.
2. До заказа согласовать с HOSTKEY использование приватного прокси для собственных устройств. Можно написать «Хочу арендовать один VPS в Амстердаме для личного приватного прокси с авторизацией, доступ только с моих устройств. Подтвердите, пожалуйста, согласование для моего аккаунта». [Правила HOSTKEY](https://hostkey.ru/about-us/legal/rules/) · [Поддержка](https://hostkey.ru/customer-care/)
3. Выбрать **Netherlands / Amsterdam**, **vm.pico**, **Ubuntu 24.04**, один публичный IPv4 и помесячную оплату. В каталоге указаны 1 vCPU, 1 ГБ RAM, SSD 40 ГБ и 490 ₽/мес. Сверить полную сумму за выбранную конфигурацию в корзине. [Заказ VPS в Нидерландах](https://hostkey.ru/vps/vps-netherlands/) · [Каталог конфигураций](https://hostkey.ru/documentation/server_order/vps_list/)
4. Добавить публичный SSH-ключ из файла `~/.ssh/outpost_ed25519.pub`. Outpost использует SSH-доступ root на новом VPS. Для пилота нужны TCP 443, 2053, 8443, 9443 и UDP 443, 2443. Если используется Let's Encrypt, разрешить также TCP 80. Сохранить IP, цену и дату оплаты.

## Профили

Указать в локальном `.env` путь к приватному ключу через `OUTPOST_SSH_PRIVATE_KEY_FILE`. Параметры DNS описаны в [инструкции по сертификатам](dns-tls.md). На новой выделенной под пилот машине команда установит Xray и sing-box. Если уже есть работающий HOSTKEY с действующим профилем, использовать его экспорт для проверки. Команда adopt предназначена для новой выделенной машины.

```sh
uv run outpost adopt --pilot --provider hostkey --country NL --ip <IPv4> --name hostkey-amsterdam
uv run outpost list
uv run outpost pilot trial --node <id> --out state/pilot-private/trial.txt
```

Временный файл содержит секретные ссылки для пробного импорта в Happ. Будут доступны REALITY на двух TCP-портах, XHTTP/H2, Trojan, Hysteria 2 с Salamander и Hysteria 2 с Gecko. В этом проекте Gecko обслуживает Xray. Эксперименты на одном адресе позволяют сравнить транспорт.

Для контроля указать в `.env` путь к приватному файлу с одной действующей ссылкой VLESS REALITY в `OUTPOST_HAPP_CONTROL_FILE`, IPv4 сервера и ожидаемого прямого выхода в `OUTPOST_HAPP_CONTROL_IP`, двухбуквенный код страны в `OUTPOST_HAPP_CONTROL_COUNTRY`. Этот клиентский профиль добавляется в локальный рендер вместе с ранее настроенным SOCKS-профилем. Импортированный контроль должен вести непосредственно на указанный узел.

## Замеры и допуск

На устройстве для проверок нужны curl, Python с зависимостями проекта и Xray с поддержкой XHTTP и Gecko. Для интеграционной проверки использовался Xray 26.11.9. Указать путь к исполняемому файлу в `OUTPOST_XRAY`, если его нет в PATH. [Релизы Xray](https://github.com/XTLS/Xray-core/releases)

На Mac проверка выполняется по команде. Каждый тест использует один локальный SOCKS-вход с одноразовым паролем, проверяет страну физического подключения, ожидаемый IP и страну выхода, затем загружает 1 МиБ через этот же профиль.

```sh
uv run outpost pilot run --interface en0
uv run outpost pilot report
```

Для отдельного устройства в РФ экспортировать клиентский манифест и перенести его приватно. Устройство получает только параметры клиентских подключений. Указать на нём путь к манифесту через `OUTPOST_PILOT_TARGETS`, каталог для результатов через `OUTPOST_STATE_DIR` и имя физического интерфейса. Команда `run` выполняет один цикл. После переноса сборщик на **отдельном устройстве** может вызывать её каждые 15 минут. Привязка сокетов к интерфейсу должна быть доступна пользователю процесса.

```sh
# На машине оператора
uv run outpost pilot export-targets --out state/pilot-private/targets.json
# На устройстве в российской сети
uv run outpost pilot run --interface eth0
uv run outpost pilot export-samples --out samples.json
# На машине оператора после передачи файла с доверенного устройства
uv run outpost pilot import-samples samples.json
```

На телефоне утром и вечером выключить Wi-Fi, выбрать конкретный профиль в Happ, проверить IP и страну, посмотреть 10 минут YouTube, открыть медиа Telegram и скачать файл GitHub. Результат записать по каждому профилю. Для неуспешной проверки воспользоваться флагом `--no-youtube`, `--no-telegram` или `--no-github`. Отмечать наблюдаемый IP и страну, при недоступном выходе указывать `unknown`.

```sh
uv run outpost pilot mobile --node <id> --profile reality-443 --operator <оператор> --version <Happ> \
  --exit-ip <IPv4> --country NL --youtube --telegram --github
uv run outpost pilot approve --node <id> --profile reality-443
uv run outpost render --happ --out dist-subs
```

Допуску нужны 72 часа наблюдений, ≥260 из последних 288 завершённых 15-минутных интервалов, ≥99% успешных среди измеренных, свежий успех и мобильные проверки утром и вечером за три дня. Первый результат интервала определяет его исход. Импорт замеров пересчитывает допуск по всем пилотным профилям. Для отдельного пересчёта после записи мобильных тестов есть `outpost pilot reconcile`. Три подряд измеренных интервала со сбоем снимают допуск при пересчёте. Причина отказа при допуске выводится в CLI. Во время ожидания отдельного устройства работают пробные ссылки. Обычный рендер включает допущенные профили. Изменение IP, порта или параметров ссылки требует новых измерений. Для публикации в частной Kubernetes-подписке использовать существующую [процедуру GitOps](happ.md#private-kubernetes-feed) с проверенным рендером.

## Состояние, расходы и обновления

Ежедневный таймер systemd на пилотном VPS сохраняет до 31 дня агрегированных счётчиков служб, перезапусков, трафика, потерь интерфейса и сбросов TCP, включая срок сертификата. Сбросы TCP относятся ко всему хосту. Счётчики после перезагрузки отсчитываются от нового boot ID. Для UDP обрывы оцениваются по активным проверкам и поведению приложения.

```sh
uv run outpost pilot server-report <id>
uv run outpost pilot account hostkey --currency RUB --balance <остаток> \
  --monthly <прогноз-с-IPv4> --eur-rate <евро-за-рубль> --due <YYYY-MM-DD>
uv run outpost pilot report
```

Суммы, курс и остаток трафика (`--remaining-gb`) записываются по кабинету. Указать все площадки, включая Hostkey, для полного прогноза. Сводка показывает дату сверки, предупреждение за семь дней до оплаты и при прогнозе от €48 для бюджета €60. Покупки, пополнения и удаления подтверждает владелец в кабинете.

Для обновления выбрать один узел, подготовить проверенный Linux-бинарник для архитектуры VPS и выполнить `outpost pilot update <id> xray <binary>` или аналогичную команду для `sing-box`. Команда проверяет допущенные профили этого ядра до и после обновления, проверяет конфигурацию новым бинарником и ставит на VPS десятиминутный таймер отката на случай обрыва связи с оператором. Следующий узел обновлять после успешной проверки первого.
